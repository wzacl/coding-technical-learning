**一、11. Container With Most Water｜盛水最多的容器**

**1. 題意與解題方法：雙指標**

輸入是每根柱子的高度，輸出是選取兩根柱子能形成的最大容水面積。

```python
A_local = (r - l) * min(height[l], height[r])
```

- 寬度是兩端的索引距離 `r - l`。
- 高度由兩端較矮的柱子決定，中間柱子的高度不限制這個容器。
- 左右指標從最外側開始，每輪計算面積、更新最大值，再移動較矮端。
- 左端較矮時 `l += 1`；右端較矮時 `r -= 1`；等高時可以選擇移動其中一端。
- 以 `while l < r` 控制搜尋，兩端相遇時停止。

為什麼移動較矮端？保留較矮端、只把另一端往內移，高度上限不會提高，寬度卻縮小，面積不可能更大。因此可以排除目前較矮端，繼續搜尋。

**2. 資料結構與變數角色**

| 結構／變數 | 類型 | 角色與選擇原因 |
|---|---|---|
| `height` | `list[int]` | 題目指定的輸入；用索引直接讀取高度 |
| `l`、`r` | `int` | 目前選定的左右位置；雙指標在此是兩個整數索引 |
| `n` | `int` | 柱子的數量，用來設定右端起點 |
| `A_local` | `int` | 目前兩端形成的面積 |
| `A_max` | `int` | 已檢查組合中的最大面積，也是最後回傳值 |

不需要建立額外串列或切片，只要讀取兩端高度並保存固定數量的變數。

**3. 重要語法與判斷**

- `min(height[l], height[r])`：比較兩個端點的高度。
- `if A_local > A_max`：目前面積更大才更新紀錄。
- 使用 `while` 是因為下一輪移動哪個位置取決於當前高度，停止條件是左右端是否仍為不同位置。

**4. 手算驗證與效率**

以 `[4, 1, 5]` 為例：

| 輪次 | `l` | `r` | 面積 | 保留的最大面積 |
|---|---:|---:|---:|---:|
| 1 | 0 | 2 | `2 × 4 = 8` | 8 |
| 2 | 1 | 2 | `1 × 1 = 1` | 8 |

接著左指標前進到 2，左右相遇，停止搜尋。

- 時間：`O(n)`。每輪一端向內前進一步，最多 `n - 1` 輪。
- 額外空間：`O(1)`。只保存固定數量的變數。
- 驗證狀態：以上是手算推導；對話中未提供修正後完整版本或 Accepted 結果。

**二、12. Integer to Roman｜整數轉羅馬數字**

**1. 題意與解題方法：由大到小的貪心拆解**

輸入整數 `num`，輸出對應的羅馬數字字串。符號表由大到小排列，並包含 `900: CM`、`400: CD`、`90: XC`、`40: XL`、`9: IX`、`4: IV` 等組合。

每輪依序完成：

1. 用 `num // value` 計算目前符號可使用幾次。
2. 用 `sym * count` 產生對應字串，加入結果。
3. 用 `num % value` 保留尚未轉換的部分。
4. 繼續處理下一組較小的數值與符號。

```python
count = num // value
num = num % value
```

這套由大到小的拆解依賴羅馬數字符號表，不能直接推論所有面額問題都適用相同策略。

**2. 資料結構與變數角色**

| 結構／變數 | 類型 | 角色與選擇原因 |
|---|---|---|
| `num` | `int` | 題目輸入；每輪更新為尚未轉換的數字 |
| `value_symbols` | `list[tuple[int, str]]` | 輔助對照表；串列明確保存由大到小的處理順序 |
| 每個 `(value, sym)` | `tuple[int, str]` | 將一個數值與其羅馬符號配成一組 |
| `count` | `int` | 目前符號需要重複幾次 |
| `res` | `str` | 累積轉換後的字串，也是最後回傳值 |

本次程式採用「元組串列」作為對照表；先前討論的字典反向查詢是補充方法，沒有用在這份主程式中。

**3. 重要語法**

元組解包按照位置接收資料：

```python
value, sym = (10, "X")
```

- `value` 得到 `10`，`sym` 得到 `"X"`。
- `for value, sym in value_symbols` 會依序讀取並解包每組資料。
- `if num // value:` 是合法寫法：商為 `0` 時視為假，非零整數視為真。
- `"X" * 3` 會得到 `"XXX"`。

字典補充：`d["V"]` 是用鍵查值；如果想用數字查符號，可以建立反向字典：

```python
reverse_d = {value: key for key, value in d.items()}
```

- 建立後，`reverse_d[5]` 得到 `"V"`。
- 原字典的值若重複，反轉後相同的鍵會被覆蓋；本次基本羅馬符號的數值沒有重複。
- 查詢不存在的鍵會引發 `KeyError`；`.get()` 可以提供預設值。
- 反向字典只做對照，不會自動將 `4` 組成 `"IV"`。

以上字典限制是補充知識，不列入本次實際錯誤紀錄。

**4. 手算驗證與效率**

以 `num = 14` 為例，較大的數值都取不到，從 10 開始有貢獻：

| 處理數值 | 商 | 加入字串 | 剩餘數字 |
|---:|---:|---|---:|
| 10 | 1 | `X` | 4 |
| 9、5 | 0 | 無 | 4 |
| 4 | 1 | `IV` | 0 |

結果是 `"XIV"`。

- 在題目 `1 ≤ num ≤ 3999` 的固定範圍下，時間與空間均可視為 `O(1)`：符號表只有 13 組，輸出長度也有固定上限。
- 這個結論不能推廣到任意長度的輸入與輸出。

**三、15. 3Sum｜三數之和**

**1. 題意與解題方法：排序＋固定一個數字＋雙指標**

輸入整數串列，找出所有總和為 0、且不重複的三元組。

- 三個元素來自不同索引，不必相鄰。
- 數值可以相同，例如三個不同位置的 0 能形成 `[0, 0, 0]`。
- 結果依數值組合去重；不同答案可以共用元素位置。

處理流程：

1. 排序，讓指標移動與數值大小具有明確關係。
2. 用外層迴圈固定 `a = nums[i]`，跳過重複的起點數值。
3. 設定 `l = i + 1`、`r = n - 1`。
4. 在 `l < r` 時，計算 `a + nums[l] + nums[r]`。
5. 依總和更新指標；找到答案後保存結果並跳過重複數值。

| 總和 | 處理 | 為什麼可以這樣移動 |
|---|---|---|
| 小於 0 | `l += 1` | 保留左端並將右端左移，總和只會不變或更小；可以排除目前左端 |
| 大於 0 | `r -= 1` | 保留右端並將左端右移，總和只會不變或更大；可以排除目前右端 |
| 等於 0 | 記錄答案、移動左指標並去重 | 保存已找到的數值組合，再搜尋新組合 |

外層用 `for` 順序走訪起點；內層用 `while`，依當前總和決定哪個指標移動。

**2. 資料結構與變數角色**

| 結構／變數 | 類型 | 角色與選擇原因 |
|---|---|---|
| `nums` | `list[int]` | 題目輸入；排序後可用索引搜尋，`nums.sort()` 會修改原串列 |
| `res` | `list[list[int]]` | 結果串列，每筆保存一組三個數值 |
| `i` | `int` | 固定的第一個位置 |
| `a` | `int` | 第一個位置的數值，等於 `nums[i]` |
| `l`、`r` | `int` | 在 `i` 右側搜尋的兩個位置 |
| `threesums` | `int` | 當前三個數值的總和 |

搜尋時維持 `i < l < r`，因此不會將同一個位置重複用在同一組答案中。這個版本透過排序與跳過重複值去重，不需要額外的 `set`。

**3. 重要語法：enumerate**

```python
for i, a in enumerate(nums):
    ...
```

在本題等價於：

```python
for i in range(len(nums)):
    a = nums[i]
    ...
```

`enumerate` 同時提供索引與數值：`i` 用於設定搜尋起點、檢查上一個元素，`a` 用於計算總和。它是方便的語法，不是此題必要的演算法。

**4. 重要判斷：兩層去重**

外層跳過重複的第一個數字：

```python
if i > 0 and a == nums[i - 1]:
    continue
```

- 排序後，相同數值會相鄰；前一輪已使用相同第一個數字搜尋，本輪可以跳過。
- `i > 0` 確認有上一個元素，避免把第一個元素與 `nums[-1]` 指向的最後一個元素比較。
- 這個 `continue` 位於外層 `for`，會前往下一個 `i`。

找到答案後，跳過重複的左側數值：

```python
res.append([a, nums[l], nums[r]])
l += 1
while l < r and nums[l] == nums[l - 1]:
    l += 1
```

- `append` 保存目前三個數值。
- 第一個 `l += 1` 讓搜尋前進。
- 內層 `while` 跳過所有連續相同的左側數值；相同值可能出現多次，所以需要反覆檢查。
- 固定 `a` 和左側數值後，右側所需數值就是 `-a - nums[l]`，再使用相同左側數值只會得到相同三元組。

你最後版本找到答案後只移動 `l` 是可行的。換成新的左側數值後重新計算總和，需要降低總和時，再由大於 0 的分支移動 `r`。

**5. 狀態追蹤、驗證與效率**

以排序後的 `[-2, 0, 0, 1, 1, 2]` 為例，固定 `a = -2`：

| 步驟 | `l` | `r` | 總和／處理 |
|---|---:|---:|---|
| 初次搜尋 | 1 | 5 | `-2 + 0 + 2 = 0`，加入 `[-2, 0, 2]` |
| 左指標前進後檢查重複 | 2 | 5 | 新值仍是 0，繼續將 `l` 移至 3 |
| 再次計算 | 3 | 5 | `-2 + 1 + 2 = 1`，將 `r` 移至 4 |
| 找到下一組 | 3 | 4 | `-2 + 1 + 1 = 0`，加入 `[-2, 1, 1]` |
| 停止本輪搜尋 | 4 | 4 | `l < r` 不成立 |
